## 2. K2：候选版本评估框架

评估候选必须满足：**有可访问源码仓库 + 明确 commit**，不接受只拿到预编译镜像的方案。

| 候选 | 目标定位 | 需要确认的问题 | 状态 |
| --- | --- | --- | --- |
| Linux 4.19（CAF/上游 msm-4.19 路线） | 中间升级目标；比 4.9 新，但不是现代 GKI | 是否有可用的 SDM845 + 小米/高通代码源？驱动（相机/指纹/NFC）覆盖？设备树迁移量？ | **未调研** |
| Linux 5.4（Android common android12-5.4 等） | 更高目标的第一档 | SDM845 社区移植现状？vendor HAL 兼容性？ | **未调研** |
| Linux 5.10+（android13-5.10 / android14-6.1 等） | 说明书首选方向 | 全硬件驱动覆盖几乎不可能；只能作为研究方向 | **未调研** |

> 说明：Android GKI 兼容矩阵只说明某个内核版本可用于某 Android 版本，**不保证**旧款 SDM845 设备的厂商驱动、
> 模块、设备树、vendor 接口可用。不得把 GKI 预编译内核直接塞给 polaris。

## 3. K2 评估判据（每项候选必须逐条填）

1. 源码仓库 URL + 分支 + commit；许可证与维护活跃度。
2. SDM845 平台支持：SoC 级代码、时钟/电源/互连、GPU、显示、音频 DSP、调制解调器。
3. 设备驱动覆盖：显示、触摸、充电、电源管理、Wi-Fi、蓝牙、音频、相机、指纹、NFC、GPS、传感器、
   休眠/唤醒、USB/ADB。
4. 模块 ABI 与 vendor 接口：Android HAL（`hardware/xiaomi`、`vendor` blob 的 ioctl/sysfs 依赖）。
5. 设备树/DTBO：polaris 的 DTS 与 sdm845-common 的差异、DTBO 编译链。
6. 编译可行性：clang 版本、内核 Makefile 与 Android 构建系统集成。
7. 风险与工作量：每项缺口的估计人日与阻塞等级。

## 4. 验收（K3/K4）

- K3：先启动，再逐项验证硬件；每项要有"通过/失败/未测"三态记录，失败要留日志。
- K4：选最终版本。若只能在 4.9 上运行 Android 16，必须标注为
  **"平台移植成功、内核升级未完成"**，不得声称内核已升级。

## 5. 下一步（K2-01 起）

1. 由方案甲/方案乙分头调研 4.19、5.4、5.10+ 的真实源码来源（记录仓库、分支、commit）。

3. 裁决通过后才允许创建内核分支与编译脚本（K3-01，注入官）。
